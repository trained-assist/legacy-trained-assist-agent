# Speech — Единый стандарт распознавания речи (`speech_transcribe`)

**Домен:** речь/аудио (распознавание) — голосовые Telegram, аудио/видео-файлы, записи звонков
**Эпик:** Ф0 «Репка с 1 инструментом» (`projects/dev-agent-engines-mcp-gtd/speech-epic-2026-09-28.md`)
**Статус сценария:** 🔵 новое (Ф0 — вынос движка; шаги с 🟣 помечены как будущие фазы, не в этом PR)
**Инвентарь факта:** `speech-tooling-inventory-2026-09-28.md` (6 независимых копий Deepgram-вызова)

---

## Ценность (результат для актора)

**Актор:** пользователь агента (владелец профиля) — присылает голосовое/аудио/видео или указывает файл/ссылку.

**Ценность одной фразой:** пользователь получает распознанный текст своей речи от **одного
общего инструмента** `speech_transcribe`, а не от шести независимых копий Deepgram-вызова —
поэтому будущие возможности (роли говорящих, словарь терминов, конспект звонка) расширяют
**один контракт**, а не правят каждое место отдельно.

**Уровень доказанности ценности: V1** — экспертная оценка инженера/владельца: вынос запрошен
владельцем как архитектурное решение, внешних пользователей у самого выноса нет.
Существующая функция (голосовое → текст) в проде и используется ежедневно (≈90 голосовых
файлов в `media/intake` профиля) — **V5 для «распознавание работает»**, но именно **вынос**
(Ф0) пользовательской ценности не добавляет: это платформа под Ф1–Ф5.
Ближайшая пользовательская фаза (Ф3 «конспект звонка») имеет рыночные аналоги
(Granola/Otter/Fathom), но research не проведён → V2, неподтверждено.

**Риск, названный явно:** ценность Ф0 не подтверждена внешними пользователями (V1) —
риск сделать работу, которая «просто переставит код». Смягчение: Ф0 сознательно ограничен
(см. Не-цели) и его единственная измеримая ценность — **не деградировать** существующее
распознавание и дать контракт, который переживёт Ф1–Ф5 без переписывания.

## Шаги

### Шаг 0 (setup) — Ключ Deepgram: сохранить / проверить

```
Агент: speech_set_key(key="<deepgram key>")      # MCP-тул, перенос video_set_deepgram_key
Агент: speech_status()                            # MCP-тул
```

**Ожидаем:**
- КОГДА `speech_set_key` вызван с непустым ключом ТОГДА ключ записан в
  `~/agent-tokens/<USER_ID>/deepgram/key.txt` (тот же путь, что у ядра, mode `0o600`)
  и `speech_status` сообщает «ключ задан».
- КОГДА `speech_status` вызван без ключа ТОГДА возвращает `{key_present: false, last_calls: []}`
  без исключения; `last_calls` — durable-журнал метаданных вызовов (`calls.json`
  рядом с ключом: время/длительность/длина текста/ошибка, без самого текста).
- КОГДА `video_set_deepgram_key` (легаси) вызван ТОГДА он продолжает работать как алиас
  `speech_set_key` (обратная совместимость).

**Validation:**
- Файл ключа существует и непуст; `speech_status().key_present == true`.
- Легаси-имя `video_set_deepgram_key` присутствует в реестре тулов и резолвится.

### Шаг 1 — Распознать локальный файл

```
Агент/пользователь: speech_transcribe(source="/…/media/intake/<hash>-audio.ogg",
                                      language="ru")
```

**Ожидаем:**
- КОГДА `source` — существующий локальный путь ТОГДА инструмент читает файл и вызывает
  Deepgram `model=nova-2&language=ru&smart_format=true`.
- КОГДА распознавание успешно ТОГДА ответ `{text, duration, language, cost_hint}`;
  `text` — непустая строка без отказа-заглушки («Извините, но я не могу…»).
- КОГДА `language` не задан ТОГДА используется `"ru"`.
- КОГДА `diarize=false` и `keywords=[]` (значения по умолчанию) ТОГДА поля `segments`/`speakers`
  в ответе отсутствуют (задел на Ф1/Ф2 не активен).
- КОГДА `diarize=true` или задан непустой `keywords` ТОГДА типизированная ошибка
  `feature_disabled` — задел зарезервирован, поведения в Ф0 нет; молчаливое игнорирование
  флага запрещено (иначе Юзер решит, что диаризация сработала).

**Validation:**
- Ответ парсится как JSON со схемой `{text: string, duration: number, language: string, cost_hint}`.
- `cost_hint` не содержит выдуманной цены: для Nova-2 цена на странице Deepgram не
  публикуется — поле отдаёт `duration_sec` и явную пометку об этом.
- `text` непустой; сравнение с эталонным транскриптом из `media/intake` (нормализация
  регистра/пунктуации) даёт similarity ≥ 0.9 (порог смоука; см. Риски R3).

### Шаг 2 — Распознать по ссылке (URL / Яндекс.Диск)

```
Агент: speech_transcribe(source="https://…/audio.mp3")
```

**Ожидаем:**
- КОГДА `source` — http(s) URL ТОГДА инструмент скачивает его во временный файл и распознаёт;
  временный файл удаляется после вызова в `finally` (и при успехе, и при ошибке).
- КОГДА источник — видео-контейнер (`.mp4 .mkv .mov …`) ТОГДА типизированная ошибка
  `unsupported_source` с подсказкой передать аудио (скил аудио-only; видео декодирует
  `video_analyze_batch`).
- КОГДА `source` — публичная ссылка Яндекс.Диска ТОГДА ссылка разрешается в прямой файл
  (как уже умеет `video_analyze_batch`) и распознаётся.
- КОГДА источник недоступен (404/таймаут) ТОГДА понятная ошибка без стектрейса.

**Validation:**
- Скачанный временный файл не остаётся на диске после вызова (проверка `tmp`).
- Ответ содержит непустой `text` либо типизированную ошибку.

### Шаг 3 — Чейн ядра не меняется (видео/интервью)

```
Пользователь: разбери видео <путь>
Ядро: video_analyze_batch → ffmpeg(-vn, -c:a libopus -b:a 24k) → speech_transcribe → interview_analyze
```

**Ожидаем:**
- КОГДА ядро вызывает `video_analyze_batch` ТОГДА оно по-прежнему отклеивает аудио через
  ffmpeg (`-vn`, opus 24k), ведёт ledger идемпотентности и чейнит в `interview_analyze`.
- КОГДА распознавание выполняет `speech_transcribe` ТОГДА ядро **не содержит** кода
  `deepgramTranscribe`/`loadDeepgramKey`/`keyDir` (в `95-video-analysis.js` их нет).
- КОГДА `video_analyze_batch` вызван повторно на том же файле ТОГДА срабатывает ledger и
  повторного распознавания нет.

**Validation:**
- `grep` по `95-video-analysis.js`: нет `deepgramTranscribe`/`loadDeepgramKey`.
- Существующий контракт `video_analyze_batch`/`video_analysis_status` неизменен (те же поля ответа).
- Повторный вызов не увеличивает число обращений к Deepgram (ledger-проверка).

### Шаг 4 — Смоук на реальном аудио (приёмка Ф0)

```
Смоук: взять <hash>-audio.ogg из media/intake → speech_transcribe → сверить с
       <hash>-transcript-<msgId>.txt
```

**Пара «аудио ↔ транскрипт» на диске (правило, проверено 28.09.2026).** Общего префикса
у имён НЕТ: шлюз `trained-assist-tg-bot` называет файлы
`sha256(chat.id:message_id:file_unique_id[:suffix])` — у аудио `suffix=''`, у транскрипта
`suffix='transcript'` (`src/lib/intake-files.js`). На фактическом `media/intake`
профиля: 97 аудио / 97 транскриптов, пересечение по префиксу = 0.
**Правило пары:** брать аудио с наибольшим `mtime` ≤ `mtime` транскрипта (на текущем
профиле — все 97 пар, Δ 0.1–0.5 с, неоднозначных нет); смоук печатает выбранные пару
и Δ, при Δ > 5 с или отсутствии кандидата — падает с объяснением, а не «подгоняет» пару.

**Ожидаем:**
- КОГДА смоук запущен ТОГДА реальный аудиофайл распознаётся через `speech_transcribe` и
  результат сверяется с уже лежащим транскриптом (пара — по правилу выше; не точное
  равенство — нормализованное сравнение регистра/пунктуации/пробелов, similarity ≥ 0.9).
- КОГДА `speech_transcribe` недоступен (скил не подключён) ТОГДА ядро падает с явной
  ошибкой «speech-skill не подключён», а не молча возвращает пустой текст.

**Validation:**
- Смоук-скрипт печатает выбранную пару (файл аудио + файл транскрипта + Δ mtime), обе длины
  и similarity; завершается 0 при пороге и не падает «зелёным» при отсутствии пары.
- Контрактные тесты скила (`tests/contract`) и CI зелёные.

## 🟣 Будущие фазы (вне этого PR — только чтобы контракт их выдержал)

| Фаза | Триггер пользователя | Ожидаем (эскиз) |
|---|---|---|
| 🟣 Ф1 диаризация | «кто это говорил?» | `speech_transcribe(diarize=true)` → `segments[]` с `speaker` + `speakers[]`; роли «рекрутер/кандидат» |
| 🟣 Ф2 словарь | «почему распознало криво имя/термин?» | `speech_transcribe(keywords=[…])` читает `projects/<проект>/vocabulary.txt` (Nova-3 `keyterm`) |

| 🟣 Ф5 durable | «где текст голосового неделю назад?» | транскрипт живёт отдельно от TTL-48ч-медиа |

**Проверка контракта на выдержку:** поля `keywords` и `diarize` присутствуют в схеме
`speech_transcribe` уже в Ф0, но по умолчанию выключены — чтобы Ф1/Ф2 не меняли контракт.

## Не-цели (сознательно НЕ делаем в Ф0)

- Диаризация, роли говорящих, определение «кто в комнате» (Ф1).
- Словарь/`keyterm`/`keywords` в деле, переход Nova-2 → Nova-3 (Ф2).
- Конспект/саммари звонка (Ф3).
- Перевод 3 инлайновых вызовов в шлюзе `trained-assist-tg-bot` на HTTP-эндпоинт (Ф4) —
  воркер не может `require()` node-скил, нужен отдельный эндпоинт.
- Durable-хранилище транскриптов, отдельное от TTL-медиа (Ф5).
- Энроллмент голоса (голосовые отпечатки) — снят в эпике по надёжности/юридике.
- Изменение интерфейса `video_analyze_batch`/`video_analysis_status` — только внутренняя реализация.

## Крайние случаи

- **Нет ключа Deepgram** → `speech_status().key_present == false`; `speech_transcribe` даёт
  понятную ошибку «ключ не задан», не 500.
- **Внешний сервис 5xx/timeout** → ретрай (как сейчас в ядре), затем типизированная ошибка.
- **Пустой/битый/не-аудио файл** → понятная ошибка, без падения смоука.
- **Повторный вызов того же файла** → идемпотентность через ledger **в ядре** (не в скиле).
- **Язык ≠ ru** → `language` переопределяется вызывающим; дефолт ru.
- **Файл сверх лимита Deepgram** → предупредить/разбить (открытый крайний случай).
- **Профиль без прав/без ключа** → изоляция по `USER_ID` (ключ per-user), чужой ключ не используется.
  NB: у профиля может не быть **своего** ключа вообще — голосовые в Telegram распознаёт шлюз
  своим глобальным секретом, а MCP-путь ключа не требует. Тогда смоук берёт ключ у владельца
  или прогоняется с разовым env-оверрайдом `DEEPGRAM_KEY` (в файл не пишется).

## Открытые вопросы (закрыты рекомендацией, помечены как риск)

- **R1 (закрыт):** `video_set_deepgram_key` остаётся алиасом `speech_set_key` (deprecated) —
  обратная совместимость, откат без боли. *Рекомендация принята как дефолт.*
- **R2 (закрыт):** путь ключа не меняется (`agent-tokens/<USER_ID>/deepgram/key.txt`) →
  миграция не нужна. *Факт из инвентаря.*
- **R3 (риск):** смоук-сверка — не точное равенство: Deepgram может дать слегка иной текст.
  Порог similarity ≥ 0.9 нормализованного текста. *Уточнить при первой гонке смоука.*
- **R4 (правка 28.09, шаг propose-change):** репо `trained-assist-speech-skill` создаётся
  под org `trained-assist`, **public** (не private), по форме `trained-assist-sales-skill`
  (эталон обязательного минимума) + манифесты из формы hh-skill. Причина: все пять
  существующих сиблингов публичные, и оба CI-цикла клонируют их **без токена** —
  приватный репо сделал бы обязательный `staging-gate` красным (`GITHUB_TOKEN` доступа к
  чужому репо в орге не даёт). Владелец просил «по образцу hh-skill». Детали —
  `03-proposal-design.md` §2.8.
- **R5 (риск):** цена и качество на Nova-3 (Ф2) не решены — вне Ф0.
