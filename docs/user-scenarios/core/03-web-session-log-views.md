## Зачем

Под каждым ответом агента в вебе есть «🧠 Полный лог» — сырой технический журнал событий движка. Он честен, но им нельзя быстро понять, **чем сессия занималась** и **что в ней осталось ценного**.

«📋 Сжатый лог» даёт вторую, человеческую проекцию того же диалога: чем занимались и сколько минут, что нашли за артефактами (контакты/PI отдельно от ссылок/документов), и короткую сводку по-русски. Обе кнопки стоят рядом — выбор проекции, а не двух разных инструментов.

Ценность: понять часовой журнал за секунду, не читая его.

## Термины

- **Проход A (детерминированный)**: ведра по семействам инструментов с минутами по timestamps трейса + артефакты через существующие детекторы (`post-tool-use-artifacts.js`) плюс новые — телефон и класс PI (телефон/e-mail/IP) против атрибутов (ссылки/документы/компании/тикеты). Без модели, бесплатно, одинаковый вход → одинаковый выход. С 29.09 Pass A даёт ещё и **facts** — по семействам (файлы/сайты/GitHub/команды/публикации/контекст) конкретные объекты: пути, URL, репозитории, команды.
- **Проход B (один бесплатный вызов)**: сводка и названия занятий по сжатой проекции, JSON-контракт `{activities:[{label,minutes}], summary}` по-русски. «Деньги только за названия»: минуты всегда из прохода A, модель их не задаёт. С 29.09 модель получает на вход только `facts` и обязана пересказать их, а промпт прямо запрещает оценки («не состоялась», «успешно», «ничего не сделано»); `facts` в ответе проходят детерминированно и моделью не меняются.
- **Пустой вход → честный ответ без модели**: нет событий и нет содержательных сообщений → `empty:true`, `message:"Лог недоступен"`, **ноль LLM-вызовов**, кэш-файл не пишется (пустой ответ не должен пережить события, которых на момент клика ещё не было).
- **Durable store трассы**: «Полный лог» читает движковую SQLite (там есть рассуждения), а при пустой/отсутствующей базе падает на собственный store на диске — `<workDir>/.session-traces/<engine>-<engineSessionId>.jsonl`, по строке на стримированную часть. Пишет раннер в момент стриминга, best-effort (сбой записи ≠ провал рана), потолок 4000 строк на файл, TTL 7 дней, права 0600. Ключ несёт движка, поэтому writer для claude/codex подключится позже без миграции.
- **Потолок простоя (`MAX_IDLE_GAP_MS`, 2 часа)**: пауза длиннее 2 часов между соседними событиями/репликами не считается работой. Иначе нить, растянувшаяся на неделю, показывала бы неделю работы.
- **Версия формата (`DIGEST_FORMAT_VERSION`)**: входит в ключ кэша. Смена семантики расчёта инвалидирует все сохранённые дайджесты — иначе старый (ошибочный) результат жил бы до 7 дней по TTL.
- **Деградация**: сессия без opencode-трейса (движок claude/локальный импорт) → сводка строится из сообщений сессии, engine = null, кнопка всё равно есть.

## Не-цели (сознательно не делаем)

- Сжатый лог **не заменяет** Полный: это вторая проекция, не агрегатор и не поиск.
- Модель не задаёт минуты — только названия. Цифры всегда из детерминированного прохода.
- **Сжатый лог не делает оценочных выводов** («сессия не состоялась», «работал хорошо») — только факты из событий; при отсутствии данных — честный «Лог недоступен».
- **При пустых данных модель не вызывается**: «Лог недоступен» — детерминированный ответ, не сводка LLM.
- **Durability «Полного лога» достигается нашим store на диске**, а не продлением жизни движковой SQLite (её ротация — штатное поведение движка).
- Никакой новой модели доступа: всё, что видно в «Полном логе», видно и здесь, и наоборот.
- Работа с **чужими** профилями не входит в сценарий: дайджест и лог читаются только в рамках своего профиля.

## Крайние случаи

- **Сообщений 1–2** → занятий нет (интервал нулевой), сводка и артефакты есть, кнопка работает.
- **Трасса нет, сообщений мало** → `engine: null`, дайджест из сообщений.
- **Провал LLM после ретрая** → детерминированная часть без summary, ошибка не показывается.
- **Свежая сессия растёт прямо сейчас** → ключ меняется, каждый клик пересчитывает (дорогого ничего: детерминированный проход лёгкий, LLM один вызов).
- **PI и атрибуты в одном сообщении** → PI уходит в свою группу «🔑 Контакты и PI», остальное — в «📎 Ссылки и документы» и т.п.; пересечений нет.
- **Ни событий, ни сообщений с содержанием** → «Лог недоступен», без LLM (DL-10).
- **Движковая БД ротировалась после части сессии** → store содержит события с момента запуска фикса; события, стримленные ДО деплоя, не восстанавливаются — лог честно частичный, читается из store (DL-12).
- **Событие есть и в движковой БД, и в нашем store** → источник выбирается целиком: движковая база (в ней есть рассуждения) приоритетна, store — fallback. Смешивания двух источников в один ответ нет, поэтому дубликатов не бывает by construction (DL-13).
- **Продолжение сессии после деплоя** → движок минтит новый engine-session id, поэтому продолжение пишет **новый** store-файл; агрегирование всех прогонов одной s-сессии в один лог — вне объёма фикса (DL-13).
- **Очень длинное рассуждение** → сжатый лог показывает его фрагмент-контекст, не интегральную оценку (DL-11).

## Известные ограничения и что осталось за рамками

- **Store не хранит рассуждения** — движок их не отдаёт в потоке. Там, где движковая база ещё жива, рассуждения приходят из неё (`reasoning: true`); из store — `reasoning: false`. Это не дефект, а свойство источника, и ответ честно это сообщает.
- **Store пишет только opencode.** Формат и ключ рассчитаны на claude/codex, но writer-ов для них нет — подключаются позже без миграции (R5).
- **Агрегация прогонов одной s-сессии** (resume → новый engine-session id → новый файл) в один лог не сделана: для этого нужен маппинг s-сессия → набор engine-сессий, это отдельная задача, не блокер.
- **`prune` чистит только каталог того профиля, который сейчас пишет.** Замолчавший профиль держит старые файлы дольше 7 дней. Десятки КБ на файл при потолке 4000 строк — косметика, не риск.
