# User Scenarios

Живая документация пользовательских сценариев. Используется как:
1. **Спецификация поведения** — что должен делать бот, точно и без двусмысленностей
2. **Основа для тестирования** — каждый шаг сценария = тест-кейс
3. **Онбординг** — новый разработчик читает сценарии и понимает систему

## Цели и скоуп

`GOALS.md` — продуктовые цели и явный out-of-scope список. Это источник истины
для автоматического гейта релевантности (стадия «Фиксер», `src/issue-fixer.js`):
он решает, чинить ли issue автоматически, читая этот файл и сценарии ниже, а не
хардкод в промпте.

## Формат сценария

Каждый `.md` файл содержит:
- **Контекст** — что уже есть у пользователя (state), какие токены подключены
- **Шаги** — реплики пользователя → ожидаемое поведение бота
- **Validation** — что именно проверяем (конкретно: файл создан, API вызван, текст содержит)
- **Edge cases** — граничные случаи в этом сценарии

## Запуск

Сейчас сценарии — только документация. Следующий шаг — runner, который их исполняет.
Планируемый runner: `tests/scenario-runner/` — отправляет шаги через `/run` API, судья-LLM оценивает ответы.
