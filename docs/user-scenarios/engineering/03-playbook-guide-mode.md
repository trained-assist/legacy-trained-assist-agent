# Engineering — Режим «гайд» плейбука: шаги как чек-лист в живом диалоге

**Домен:** плейбуки (эпик #1887, п.1 — режим «гайд»)
**Профиль:** любой профиль, запускающий плейбук для мелкой задачи или задачи «давай обсудим»
**Тулы:** `playbook_run({playbook_id, goal, mode?})` (`src/mcp-skills/tools/102-playbooks.js`), выбор режима
`src/playbook-guide.js`, компилятор `src/playbook-compiler.js`, `checklist.md` проекта, GTD-контроллер
**Базовый сценарий:** `01-development-playbook.md` (фоновый durable-путь) — гайд описывает альтернативный режим того же плейбука
**Охват:** только п.1 #1887. п.2 (вопрос всплывает в чат-владелец для фоновых планов, после #1886)
и п.3 (флаг `interactive: true` у шага) — отдельные срезы, здесь НЕ входят.

## Ценность

**Одна фраза:** пользователь, которому нужно пройти плейбук для мелкой или обсуждаемой задачи,
получает шаги как **живой чек-лист в текущем диалоге** и двигает его с агентом пошагово — без
молчащего фонового плана и без шагов, висящих «в ожидании ответа»; объективные гейты (CI/staging)
остаются обязательными.

**Доказанность: V4.** Источники:
- Владелец в голосе 2026-09-29 (issue #1887): «сейчас плейбук = фоновый план, который уходит в фон и
  молчит… нет режима обсуждения», «шаг паркуется в „ждём ответа“ (blocked by user), а вопрос появляется
  как служебная вставка в чужих сессиях». Требование записано в requirements-log **[140]**.
- Обходной путь уже реально используется: прогресс плейбуков ведётся **руками в `checklist.md` проекта**
  (текст #1887 — «как делается руками сейчас»); профиль PO ведёт так планы на ежедневной основе
  (напр. этот самый эпик, скриншоты в рабочих папках планов). То есть пользователь уже «платит» руками за
  то, что гайд-режим даст автоматически.

## Контекст (начальный state)

- Пользователь в **живой сессии Telegram** — текущий диалог с агентом.
- Плейбук сохранён и виден через резолв (profile → sibling → system), напр. `development` или профильный.
- **Решение владельца 29.09 19:00:** в Telegram гайд — режим **по умолчанию**; режим выбирает код
  `playbook_run` (`src/playbook-guide.js`), а не правило промпта. Веб и неинтерактивные вызовы
  (шаги фоновых планов `s-plan-*`, cron, внутренние) остаются фоном.

## Сценарий

| # | Актор → блок | КОГДА … ТОГДА … |
|---|---|---|
| 1 | Юзер в Telegram согласовал задачу («делай», «давай», кнопка) | КОГДА агент вызывает `playbook_run({playbook_id, goal})` без `mode` и в этом чате нет открытого гайда ТОГДА код выбирает гайд: `mode:"guide"`, `mode_reason:"default_telegram"` |
| 2 | Юзер явно просит фон («в фоне», «параллельно», «сам доделай») | КОГДА агент передаёт `mode:"background"` ТОГДА создаётся durable-план ровно как до фичи (`mode_reason:"explicit"`) |
| 2' | Второй плейбук в том же чате | КОГДА в этом чате уже открыт гайд (в любом проекте профиля) ТОГДА новый уходит в фон: `mode_reason:"foreground_busy"`, `busy:{goal}`; фоновый план НЕ привязывается к живой сессии, чтобы не выключить доводку гайда |
| 3 | `playbook_run` в режиме гайда | ТОГДА НЕ создаётся запись в `durable_tasks` и нет фоновой сессии `s-plan-<id>`; ответ содержит `steps`, `checklist_md`, `checklist_path`, `guide_hint` |
| 4 | Тул → `checklist.md` проекта | ТОГДА секцию дописывает **сам тул** (append-only): `Goal:`, `Owner-session:`, `Owner-chat:`, `Mode: guide`, `Playbook:`, `Started:` и шаги `- [ ] N. …`; выключенные шаги сразу `- [x] … выключен: причина`, гейты помечены `[ГЕЙТ, не пропускается]` |
| 5 | Шаг, которому нужен ввод юзера | КОГДА шаг требует ответа ТОГДА вопрос задаётся **обычным сообщением в той же сессии**; шаг не паркуется в «ждёт ответа» |
| 6 | Юзер отвечает | ТОГДА агент продолжает следующий шаг чек-листа |
| 7 | Гейты CI/staging | ТОГДА гейт обязателен: выключить нельзя (`STEP_PROTECTED`), закрывается только зелёной проверкой |
| 8 | Продолжение между ранами | КОГДА ран закончился с открытыми пунктами ТОГДА GTD-контроллер доводит секцию по `Owner-session` (существующий механизм, #1729) |
| 9 | Завершение | КОГДА все шаги `[x]` или в секции есть `Closed:` / `Cancelled:` ТОГДА гайд закрыт и больше не держит чат; итог — в диалоге |

## Не-цели (этого среза)

- Веб остаётся фоном (отдельный пункт эпика: сессия = план + значок).
- **Не** реализуем п.2 #1887 (всплытие вопроса в чат-владелец для фоновых планов) — блокер #1886.
- **Не** реализуем п.3 #1887 (флаг `interactive: true` у шага).
- **Не** вводим новые валидаторы и не трогаем системные гейты плейбуков.

## Крайние случаи

- **Пользователь ушёл посреди гайда.** GTD доводит по `Owner-session`; брошенный гайд перестаёт занимать чат через 24 ч без изменений файла, по `Closed:` или кнопке «✖️ Отменить».
- **У живой сессии уже активный фоновый план.** Новый плейбук → фон (`mode_reason:"session_has_plan"`), иначе GTD не повёл бы гайд этой сессии (#1719).
- **Сессия не в папке проекта** (например, в git-воркспейсе). → фон (`no_project_dir`); явный `mode:"guide"` → ошибка `GUIDE_NO_PROJECT` (или передай `project_id`).
- **`mode:"guide"` + `activate:true`.** Ошибка `MODE_CONFLICT`. Без явного `mode` `activate` на гайд не влияет.
- **Плейбук не сохранён / нет обязательного входа.** Те же ошибки, что в фоне (`PLAYBOOK_NOT_FOUND`, `INPUT_REQUIRED`) — до записи в файл.
- **Откат.** `PLAYBOOK_GUIDE_DEFAULT=0` в окружении сервиса → по умолчанию снова фон; явный `mode:"guide"` работает.

## Validation (что проверяет прод-смоук и тесты)

- Автотесты: `tests/unit/playbook-run-guide.test.js`, `tests/unit/playbook-guide.test.js`, `tests/unit/gtd-checklist-guide-meta.test.js` (`scripts/sandbox/playbook-guide-mode.sh`).
- Прод-смоук под профилем web-canary с Telegram-окружением: первый вызов → гайд, секция в checklist.md, durable-задач 0; второй в том же чате → фон `foreground_busy`; явный `mode:"background"` → фон.
- Шаг 7: гейт из чек-листа нельзя пометить выполненным при красном CI (тот же детерминированный валидатор).
- Регрессия: веб и шаги фоновых планов без `mode` создают durable-план, как до фичи.

## Риски

- **Цена:** шаги гайда исполняет живая модель — для длинных плейбуков дороже фонового пула дешёвых моделей. Митигирует: второй план в чате → фон; «в фоне» → фон; флаг отката.
- **Ложное «занято»:** брошенный гайд держит чат не дольше 24 ч; ложное «свободно» даёт лишь гайд вместо фона.
